# VEP Arena：固定接入与验收回环

更新：2026-09-17。配合 [三层职责](architecture.md) 和 [产物契约](result_artifact_contract.md) 使用。本文件定义流程，不表示下面的自动校验功能已经全部实现。

## 一个统一的完成定义

**接入 OK = 在声明范围内，输入对应正确、处理遵守协议、输出符合约定、证据可回查。** 不是准确率超过阈值，不是超过 TRCA，也不是目录里已经有代码。

“工程接入通过”与“论文数字复现通过”分别记录。工程测试仍检查已知数值性质、标签与样本映射、状态隔离；不能以“不看准确率”为由忽略算法明显实现错误。

共同回环：

```text
声明输入/输出和支持范围
  → 最小 fixture 验证
  → 一次小规模实际执行
  → 产物/来源核对
  → 记录通过范围
  → 新增版本或修改后只重跑受影响的回归
```

fixture 是小型可重分发测试数据，可由测试生成；它验证代码和格式。真实数据检查验证实际来源，不可用 fixture 通过冒充真实数据已验收。

## A. 新数据：一层的固定回环

| 步骤 | 工作 | 通过标准/证据 |
| --- | --- | --- |
| D1 数据登记 | 在已有数据说明/配置中登记来源、版本、文件格式和能力 | 采样率、单位、轴顺序、通道、标签/刺激映射、试次时间与缺失情况有来源；不适用项明确标注 |
| D2 适配与 fixture | 沿用 `DatasetInfo` / `TrialBatch` / `SSVEPDataset` 或显式扩展 | 样本数量、轴、标签和通道顺序正确；试次能回到源文件/事件；不支持的选择明确报错 |
| D3 真实小样本核对 | 本地读取代表性的真实文件，不上传原始数据 | 与原文件字段或可信独立读法核对身份、单位、时间范围和样本值；覆盖本次声明的格式变体 |
| D4 下游与缓存检查 | 分类数据跑一个适用的已接入方法；分析数据跑对应基础分析 | 输出契约通过；冷/热缓存一致；改变数据版本、通道、裁窗或预处理不误用旧缓存 |
| D5 登记结论 | 记录版本、已验收变体、证据路径、限制 | 可声明该范围 `accepted`；未覆盖 session/格式/范式仍列出，不自动扩展为全数据已验证 |

D2 至少覆盖：非连续标签、通道顺序、block/target 子集选择、缺文件/缺事件、越界裁窗和重复试次 ID。合法缺失与损坏数据区分记录，不用补零/伪 block 静默伪造完整数据。

D3 不要求先跑全被试大实验。不同 MAT 布局、采样率或 session 结构是不同验证范围；同一格式按已有 adapter 增加被试，不必重新设计框架。

数据登记可以复用 `configs/datasets/` 和已有 README。来源文件索引与逐试次来源表按产物契约保存；不另建注册服务，不强制更换原始数据格式。

## B. 新算法：二层的固定回环

| 步骤 | 工作 | 通过标准/证据 |
| --- | --- | --- |
| M1 方法登记 | 方法 ID/实现版本、输入契约、参数、训练需求、能力与来源 | 分清网络结构和完整方法；分数列对应的类 ID 明确；预训练/参考实现来源明确 |
| M2 方法测试 | 小型确定性/合成输入与异常输入 | 形状、有限值、标签映射、参数生效、未 fit 行为和 fold 状态隔离符合声明；支持保存加载则核对重载预测 |
| M3 一次真实执行 | 使用已验收数据和一个有效的小协议 | 真正完成所需训练与预测；仅 `--help` 或 import 不算；记录 seed、有效参数与训练/验证/测试身份 |
| M4 产物与集成验收 | 按分类产物契约核对行、重建指标和来源 | 样本/预测一一对应；实际样本数正确；学习状态可回查；与另一方法的可比性检查能给出明确结论 |

M2 检查算法应有的数值/逻辑性质，可对小输入与可信参考实现做等价性验证。真实数据准确率低可记诊断警告，但“优于基线”不是通用接入门槛。

训练轮数、验证选择、预处理等由方法配置表达；不能为提高验收数字使用测试标签调参。随机方法记录 seed 和环境；重现容差预先声明，不承诺跨设备逐比特一致。

仅支持部分输入、无分数输出、无持久化或不支持在线的算法可以登记受限能力。不能将缺失能力当作已通过；相关重载/在线验收标为不适用并说明原因。正式重放需要的状态按产物契约保存。

网络模型已存在时，优先补输入/训练适配，不重新复制一份网络。旧作者代码可通过薄包装保留其行为；严格论文复现的独立核对放在对应 task。

## C. 新 task 或独立分析：三层的固定回环

| 步骤 | 工作 | 通过标准/证据 |
| --- | --- | --- |
| T1 定义问题 | README 声明输入引用、配置、入口、结果类型和检查 | 说清是识别评估、比较、信号分析或其他研究；不要求一律有分类目标 |
| T2 执行最小问题 | 调用一层/二层，保留 task 独有逻辑 | 路径/参数明确；数据和中间状态能追溯；不依赖未声明的临时变量或手工文件 |
| T3 校验产物 | 分类用分类契约；分析用 task 声明的表/数组契约 | 列含义、轴、单位、唯一键、输入覆盖、计算不变量/小型参考例子可核对 |
| T4 重建与记录 | 从已保存输入和实际参数重建派生表/图 | 图表来源明确；记录已验证范围；分析成功与研究假设成立分开 |

专题分析共享原始数据，但可以有独立算法和统计过程。它只需接好数据来源与产物边界，不必先改变核心执行器。

对比 task 额外检查：同一测试身份及划分语义、数据权限/预训练来源、校准预算、预处理差异、时间与指标定义。未知或不兼容时，禁止输出“同条件直接排名”；可以输出明确分组或探索性比较。

不能仅按 CSV 行数判断覆盖。重复记录、缺失记录、重复随机重复实验、不同训练组合须通过唯一键和 split 身份区分；配对统计的实验单位由 task 声明，不能把同一试次的重复预测当独立样本。

## D. 测试只保留三种回环，不堆新体系

| 回环 | 运行条件 | 检查内容 |
| --- | --- | --- |
| 快速契约回归 | 每次触及相关代码；无私有数据依赖 | fixture、形状/标签/时间边界、异常输入、唯一键、配置变化、计算不变量 |
| 小型集成回归 | 新数据/方法接入，或共享语义改变 | 实际读数据 → 适用方法/分析 → 产物重建；真实数据受限时在本地运行并保存证据 |
| 实验级验证 | task 明确需要时 | 全量运行、论文数字、统计结论、性能或在线回放；不是每个小改动的前置条件 |

当前已有公共测试命令，可继续使用：

```bash
uv run --with pytest python -m pytest tests/
```

数据/算法专属检查放入现有测试组织，必要的真实数据检查入口放对应 task。上表不是一组已经实现的新 CLI 命令；本轮不引入专门测试框架。

续跑涉及的最小反例必须包括：重复行凑够数量、旧被试结果匹配新被试、不同通道/参数复用输出、不同训练组合混写。未实现可靠续跑的入口应标不支持；新运行采用独立输出目录，不假装可以 resume。

## E. 一份验收记录，避免反复口头确认

正式验收在本地产物目录保存 `acceptance.json`（也可先在 README 记录同等字段，后续直接转换），记录与代码/数据/配置版本绑定。下面是**未执行模板**，不是已通过证据：

```json
{
  "schema_version": "1.0",
  "component_type": "method",
  "component_id": "example_method",
  "code_commit": null,
  "data_revision": null,
  "config_fingerprint": null,
  "scope": {
    "datasets": [],
    "protocols": [],
    "input_variants": [],
    "capabilities": []
  },
  "checks": {
    "contract": {"status": "not_run", "evidence": []},
    "real_data_smoke": {"status": "not_run", "evidence": []},
    "artifact_audit": {"status": "not_run", "evidence": []},
    "comparison": {"status": "not_run", "evidence": []}
  },
  "decision": "not_run",
  "limitations": [],
  "paper_reproduction": {"status": "not_run", "evidence": []}
}
```

检查状态仅用 `pass`、`fail`、`not_run`、`not_applicable`；不适用必须有理由。完成判定用 `accepted`、`blocked`、`not_run`：适用检查通过且证据完整才能在该 scope 标 `accepted`。纯分析可以没有 comparison 或分类检查；不能借“不适用”跳过其自身的计算正确性和输入/输出契约。

数据接入的 contract 检查记录 D1/D2，真实检查记录 D3/D4；方法记录 M1–M4；task 记录 T1–T4。`evidence` 填运行命令、运行时间、日志/产物路径或摘要与哈希；私有身份及原始数据不提交公共仓库。共享代码只有 fixture 证据时，状态必须写清真实数据范围未验收。

同一组件可有不同 scope 的记录。一次 Benchmark smoke 不能自动证明 BETA、全部窗口、全部通道配置或在线使用均通过。

## F. 改动后重跑什么

| 改动 | 必跑回环 | 不默认重做 |
| --- | --- | --- |
| 源格式、标签/时间/通道映射 | 数据契约 + 代表性真实核对 + 受影响下游集成 | 未受影响的数据 adapter |
| 预处理顺序、滤波参数或缓存键 | 预处理/缓存测试 + 受影响方法集成；更新指纹 | 无关 task 与无关方法 |
| 方法训练、预测或默认参数 | 方法测试 + 一个已有数据集集成；新实现版本 | 数据读取重构 |
| 共享划分、续跑或写出逻辑 | 反例测试 + 至少两个调用路径的小型回归 | 无关算法重写 |
| task 的分析公式/分组 | 分析参考例子 + 派生产物重建 | 上游模型重训，除非输入条件改变 |
| 图表布局、文档导航 | 链接/读表/图表检查 | 算法实验 |

影响参数或科学含义的改动产生新记录/新产物，不覆盖旧验收。只修改代码注释等不影响计算的改动，可记录已审查的继承关系，不能无解释地把旧结果标成新运行。

## G. 现在的落地顺序

先复用已有接口和产物规范，补足一个真实数据子集的身份/来源记录；再接通 EEGNetMini 与 TRCA 的实际执行及产物回读，用一条端到端回环验证这些约定。随后其他已有模型按 M1–M4 增项。

每次以一个可用能力为交付：数据可用、方法可执行、结果可比较或一个专题分析完成。兼容包装和旧产物旁路说明都可以接受；不把全仓库统一格式、全量跑分或未来在线支持作为当前交付的前置任务。
