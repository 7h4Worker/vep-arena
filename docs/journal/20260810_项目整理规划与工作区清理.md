# 2026-08-10 项目整理规划与工作区清理

## 起因

vep_arena 自 2026-06 建立以来经历了多个阶段：初始 benchmark 对比 → DNN 集成 → 
多数据集 baseline 批量 → 决策信道分析 → 跨范式分析。工作区积累了大量多世代遗留物，
tasks/ 目录扁平且命名混乱，远端仓库与本地工作严重脱节。需要系统整理。

## 讨论过程

### 1. tasks/ 目录重组方案

经过多轮讨论确定以下结构（尚未执行移动）：

- **baselines/** — 各数据集标准算法评估（推 remote）
- **channel_capacity/** — 信道容量分析链（DMC → 跨范式 → MIMO）
- **codebook/** — EMBC/JBHI 码本结构分析
- **crossparadigm/** — 跨范式元分析
- **probes/** — 探索性分析和数据集 QA

命名规则：baselines/ 下用 `{paradigm}_{dataset}` 格式，其他主题用描述性短语。

### 2. 仓库边界：公开 vs 本地

确定远端只推 baseline 基础设施（数据加载器、算法、baseline 脚本），
信道分析和跨范式分析等未发表研究内容不上远端。
详见 `docs/project_rules.md`。

### 3. 产出物分层

- `tasks/*/results/` — 单任务产出（gitignored）
- `outputs/` — 跨任务综合产出（新建，gitignored）
- `docs/journal/` — 工作日志（本地）

### 4. 文档体系

建立了 `docs/journal/` 工作日志机制和 `docs/project_rules.md` 持久规则文档。
