# Dual-Alpha 双频 SSVEP 基线复现报告（2026-07-08）

## 任务定位

本 task 负责将 Dual-Alpha / GigaDB 102557 数据集纳入 Arena 的正式分类流程。第一轮范围只覆盖能够和公开结果表直接对齐的分类基线：

- 官方 ensemble TRCA：Arena 中记为 `ETRCA`。
- 官方 FBDCCA：只覆盖 `Checkerboard_Arrangment` 与 `Binocular_Vision`，因为公开 FBDCCA CSV 没有 `Binocular-Swap_Vision` 段。

结果目录：`tasks/ssvep_dual_alpha_baselines/results/official_baselines`

## 数据与协议

- Subjects：35。
- Targets：40。
- Blocks：5。
- Sampling rate：250 Hz。
- Windows：0.2-2.0 s，步长 0.2 s。
- CV：subject-specific leave-one-block-out。
- ITR：40 类，`trial_seconds = window + 0.5`。
- 通道：`official`。CA/BV 为 9ch，BsV 为 64ch。
- Python 环境：本次 MNE-FIR 修复重跑实际使用 `D:\ProjData\envs\erp_ssvep_lab`；2026-07-09 之后 Arena `.venv` 已补齐 MNE，后续复跑应使用 `.venv\Scripts\python.exe`。

## 预处理

Dual-Alpha 与 Ke 2025 Binocular AR 的预处理入口不同。

Dual-Alpha 已经发布为 epoch-level CSV，因此本 task 直接按 epoch 裁剪窗口，然后进入方法滤波器组：

- `ETRCA/TRCA`：官方 TRCA pass/stop band，7 个 Chebyshev 子带。
- `FBDCCA`：双频 sine/cosine 模板、平方相关、固定权重、5 个有效子带，正式结果强制使用官方 MNE FIR 路径（`mne-fir`）。

Ke 2025 Binocular AR 则是连续 EEG + events，需要先做连续信号预处理、事件切窗和视觉延迟校正。因此两者进入分类器后的张量形式接近，但前置预处理并不相同。
