# NOTES 2026-07-18

## Full Run Failure and Data Coverage Guard

The first all-channel, first-five-block formal audit stopped at subject 3.
The failure was not a comb-filter or BTRCA numerical error: in subject 3,
leave-block-3-out leaves target 22 absent from the training set. A 40-target
template method cannot evaluate that fold because it has no template for the
held-out class.

`run_formal.py` now checks the 40-class coverage for every training partition
before fitting TRCA/eTRCA/bTRCA/ebTRCA. It skips only folds with incomplete
coverage, records their held-out block and missing classes in
`skipped_folds.csv`, and retains the valid folds for that subject. This keeps
the data irregularity explicit instead of substituting a synthetic template or
silently changing labels.

The full preflight over the requested first-five-block protocol found no
subject with zero valid folds. Subjects 3, 5, 7, 8, and 9 each have one
incomplete-training fold: respectively held-out blocks 3, 3, 5, 3, and 3.
Their missing training targets are respectively 22, 22, 19, 22, and 6.
All other requested subject/fold combinations retain all 40 training classes.

## Parallel and Recoverable Execution

The formal runner now supports `--workers` with subject as the parallel unit.
Workers return independent subject results; the parent is the only process
writing task outputs and checkpoints `trials.csv`, `summary.csv`,
`skipped_folds.csv`, `failures.csv`, and `manifest.json` after each completed
subject. `--resume` skips only subjects with a full requested method/window
grid, so a late dataset failure cannot discard earlier completed subjects.

The restart uses three workers while Liang2020 remains active. Each worker uses
the existing cropped 64-channel CNT loading path; BLAS threads are capped at
one for the parallel process pool.
