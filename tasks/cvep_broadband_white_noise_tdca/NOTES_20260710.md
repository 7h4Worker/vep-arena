## Method Status

The Zenodo code includes `core/spatialFilters.py` with TRCA/TDCA classes. The Arena `.venv` currently does not include `statsmodels`, so direct import fails on `from statsmodels.stats.weightstats import ttest_ind`.

Priority is to reproduce the Zenodo TDCA implementation. The task therefore adds `run_reference_tdca.py`, which imports the Zenodo TDCA class directly and provides a small `ttest_ind` shim backed by `scipy.stats.ttest_ind`. The shim only supports the confidence calculation used after prediction; the model fit/predict path remains the Zenodo implementation.

## Native Arena TDCA Quick Compare

Ran an inline comparison on S1/session1 using the same 2 leave-one-repetition folds as `reference_tdca_smoke_2fold`.

Compared methods:

- `ZENODO_TDCA`: imported directly from `extracted/core/spatialFilters.py`.
- `Arena_TDCA_WNREF_delay0`: `vep_arena.methods.tdca.TDCA`, author filter-bank bands, WN stimulus resampled to 250 Hz as class references, `n_delay=0`.
- `Arena_TDCA_WNREF_delay5`: same as above, `n_delay=5`.

Important preprocessing detail: filtering must be done on the full 1 s epoch before latency/window crop. Cropping first to 0.1 s makes `scipy.signal.filtfilt` fail because the window is shorter than the filter pad length.

Mean over 2 folds:

- 0.1 s: Zenodo TDCA accuracy 0.4906, Arena TDCA delay0 0.1813, Arena TDCA delay5 0.2844.
- 0.2 s: Zenodo TDCA accuracy 0.9250, Arena TDCA delay0 0.7656, Arena TDCA delay5 0.8375.

Conclusion: Arena native TDCA can be adapted to WN-BCI, but the current adapted form is not equivalent to the Zenodo TDCA. The Zenodo implementation remains the reference reproduction path.

## TDCA Implementation Audit

Question: whether the lower WN-BCI result from `vep_arena.methods.tdca.TDCA` indicates a broken Arena TDCA implementation.

Checks:

- HD200 S1, 40-target, 9-channel, 200 ms, leave-one-block-out, same filter-bank cache and sine/cos references:
  - Validated HD legacy TDCA formula: 705/720 correct, accuracy 0.9792.
  - Shared `vep_arena.methods.tdca.TDCA`, `n_delay=4` to produce five delayed blocks, raw weighted correlations: 709/720 correct, accuracy 0.9847.
  - Shared TDCA with signed-squared correlations: 708/720 correct, accuracy 0.9833.

This makes a general shared-TDCA implementation failure unlikely.

Additional WN-BCI S1/session1, 2-fold comparison:

- `ZENODO_TDCA`: 0.4906 at 0.1 s, 0.9250 at 0.2 s.
- `Arena_TDCA_WNREF_delay4`: 0.2719 at 0.1 s, 0.8469 at 0.2 s.
- `Arena_TDCA_EEGTEMPLATE_REF_delay4`: 0.3344 at 0.1 s, 0.8594 at 0.2 s.

Interpretation:

- Standard SSVEP TDCA does use EEG training templates. Arena shared TDCA also builds class templates from training EEG.
- The reference input controls the time-domain projection subspace, not the class template itself.
- For WN-BCI, a raw WN stimulus sequence is a poor projection basis for short-window EEG response because the visual system transforms the broadband stimulus before it appears in EEG.
- The Zenodo `TDCA` implementation is a different, dataset-specific variant: it uses class EEG evoked templates and Fisher-style spatial filters after broadband filter banks, without passing `STI.mat`/WN code sequences into TDCA and without the standard reference-projection/delay-augmentation path.

Conclusion: keep Zenodo TDCA as the strict reproduction path. Treat Arena shared TDCA on WN-BCI as an ablation unless a stimulus-to-EEG encoding model is added before building reference projections.

## SSVEP Branch Check

The Zenodo code contains placeholders for both `WN` and `SSVEP` tags in `core/classification.py` and `info/mutualINFO.py`.

The downloaded `Broadband.zip` package, however, only contains actual `data/seperate/sweep/S_*.pkl` subject files and `data/stimulation/sweep/STI.mat`. The `data/seperate/compare` directory is empty, `data/datasets` only contains `.DS_Store`, and all loaded `sweep` sessions have tag `WN`.

Therefore the local public Zenodo 8300517 package supports the WN sweep reproduction, but does not contain a usable SSVEP branch. The 160-target MFSC SSVEP dataset is a related same-lab/overlapping-author line, not the missing SSVEP split inside this Zenodo package.

## Information-Rate Bounds Reproduction (added later 2026-07-10)

Reproduced the paper's core info-rate framework (`info/bounds.py` + `info/mutualINFO.py`) directly,
adapting the loader to the individual `S_*.pkl` + `STI.mat` (the combined `sweep.pickle` the paper
scripts expect is absent). Called the Zenodo `vanilla` spatial filter and `EEG2Code` reverse-TRF
model verbatim (with a small `sklearn.minmax_scale(axis=-1)` back-compat shim for newer sklearn).

Results (10 subjects, 21 occipital channels, 1 s window):

- Upper bound (evoked-response SNR, integrated to Nyquist): **60.8 ± 21.7 bps** (paper 63 ± 20).
- Lower bound (single-trial stimulus reconstruction, cut at 30 Hz): **25.6 ± 2.9 bps** (paper 25 ± 3).

Both bounds match the paper, confirming the individual `S_*.pkl` files are numerically consistent
with the paper's combined dataset. Key band finding: discriminative info concentrates in **beta
(13–30 Hz)**, not alpha. TRF latency ~125 ms. Full analysis + figures: `analysis/spectrum_resources/`.

**Framing correction**: the earlier `analysis/decision_channel/` treated this single-target code-sweep
data as a 160-target BCI selection task (confusion-matrix MI, capacity decomposition). That framing is
inappropriate — this is single-target gaze, no target array. Deprecated. The classification MI in
`REPORT_20260710.md` remains valid but only as a **code-discriminability** measure, not selection capacity.
